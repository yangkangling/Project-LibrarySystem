# 图书馆借阅系统需求规格说明书（审核版）

- 文档状态：待审核
- 文档版本：V2.1
- 编写日期：2026-08-12
- 说明：本文件依据老师反馈重写，先描述正式图书馆借阅系统的真实业务需求。现有后台功能只作为管理员/馆员管理模块，普通读者也可以通过软件自助借书和还书。UML、数据库设计、接口设计待本需求审核通过后再开展。

## 1. 修订说明
- **系统定位**：由单一后台系统调整为完整图书馆借阅系统，包含管理员/馆员管理端、读者自助端和借阅库存核心业务。
- **现有功能定位**：现有图书、分类、读者、借书、还书、记录、逾期等功能作为系统中的管理员/馆员管理模块，不代表系统全部功能。
- **使用对象**：由“仅管理员后台”调整为“管理员/馆员端 + 普通读者自助端”。
- **登录验证**：管理员/馆员管理端需要单独输入账号密码验证；普通读者使用借阅证号或读者账号登录自助端，两类入口权限隔离。
- **借阅方式**：由“一次借一本”调整为“一次可借多本，形成一张借阅单，多条借阅明细”。
- **还书方式**：支持整单还书，也支持只归还其中部分图书；借阅单可出现部分归还状态。
- **库存管理**：增加馆藏总量、可借库存、借出数量、在架/借出/停用等状态，以及书架位置。
- **并发控制**：要求服务端在借阅提交时防止多人同时借同一库存导致超借。
- **设计顺序**：本文件仅作为需求规格说明书；UML、数据库设计和接口设计待审核通过后再开展。

## 2. 项目目标
建设一个正式的图书馆借阅系统，而不是只用于展示的简单 demo。系统整体由管理员/馆员管理端、普通读者自助端和借阅库存核心业务组成。现有图书分类、图书管理、读者管理、借书、还书、借阅记录和逾期查询等功能，定位为完整系统中的管理员/馆员管理模块。系统还需要支持普通读者在软件中查询图书、自助借书、自助还书和查看本人借阅记录。

系统需要完成图书分类、书架、库存、读者、一次多本借阅、部分还书、逾期查询和借阅记录追溯等核心业务，并保证并发借阅时库存不会被超借。

## 3. 角色与权限
| 角色 | 真实场景 | 主要权限 |
| --- | --- | --- |
| 系统管理员 | 通过管理员入口输入账号密码登录，维护系统基础配置、管理员账号、分类、货架和全局规则。 | 管理员登录、参数维护、账号维护、数据查看。 |
| 馆员 | 通过管理端账号密码登录，负责日常图书、读者、借书、还书、逾期处理。 | 图书管理、读者管理、借阅办理、归还办理、记录查询。 |
| 普通读者 | 通过读者自助端登录，查询图书、办理自助借书、查看当前借阅和自助还书。 | 读者登录、图书检索、自助借书、自助还书、查看本人记录。 |
| 系统 | 自动完成库存扣减、逾期判断、并发校验、状态流转和日志记录。 | 规则校验、事务处理、状态计算。 |

## 4. 核心业务对象
| 业务对象 | 说明 | 关键数据 |
| --- | --- | --- |
| 读者 | 使用借阅证号或读者账号识别真实借阅人。 | 借阅证号、姓名、手机号、状态、当前借阅数量、历史借阅。 |
| 图书 | 表示一种图书资料，不等同于一本实体书。 | ISBN、书名、作者、出版社、分类、馆藏总数、可借数量、书架位置、状态。 |
| 图书副本/库存 | 用于表示同一种图书的具体册数和流转状态。 | 副本编号、所属图书、所在书架、状态、是否可借。 |
| 图书分类 | 用于图书归类和筛选，新增图书时必须从已有分类中选择。 | 分类名称、说明、启用状态、图书数量。 |
| 书架 | 表示图书的真实存放位置。 | 馆区、楼层、书架编号、层位、备注。 |
| 借阅单 | 一次借书操作形成一张借阅单，可包含多本图书。 | 借阅单号、读者、借阅日期、应还日期、状态、操作人。 |
| 借阅明细 | 借阅单中的每一本书对应一条明细，支持部分归还。 | 图书/副本、借出时间、应还时间、归还时间、明细状态。 |

## 5. 功能需求
| 编号 | 模块 | 需求说明 | 验收要点 |
| --- | --- | --- | --- |
| FR-01 | 登录与权限 | 系统提供管理端登录和读者端登录两个入口。管理员/馆员必须通过账号密码验证后进入管理端；普通读者通过借阅证号或读者账号进入自助端。 | 两类用户权限隔离；未登录不得访问受保护页面；账号错误给出中文业务提示。 |
| FR-02 | 工作台 | 展示馆藏总量、可借数量、借出数量、读者数量、逾期数量和近期借阅动态。 | 所有统计从真实数据计算，不使用固定演示数字。 |
| FR-03 | 分类管理 | 支持分类新增、编辑、停用、删除、查询和分页。 | 新增/编辑图书时分类以下拉选项选择，不能手写不存在的分类。 |
| FR-04 | 书架管理 | 维护馆区、楼层、书架号、层位等位置信息。 | 图书可绑定书架位置，查询图书详情时显示所在货架。 |
| FR-05 | 图书管理 | 支持图书新增、编辑、删除/停用、查询、分页、详情查看。 | ISBN 唯一；馆藏总数不得小于已借出数量。 |
| FR-06 | 库存管理 | 系统维护馆藏总数、可借数量、借出数量和不可借数量。 | 借书成功可借数减少；还书成功可借数增加；库存不得为负。 |
| FR-07 | 读者管理 | 支持读者新增、编辑、启用、停用、查询、分页、详情查看。 | 停用读者不能新借书，但允许归还已借图书。 |
| FR-08 | 一次借阅多本 | 馆员或读者自助端可一次选择多本图书提交借阅。 | 一次提交形成一张借阅单和多条借阅明细。 |
| FR-09 | 借阅校验 | 提交借阅前校验读者状态、借阅上限、图书状态、库存、重复借阅和应还日期。 | 任一校验失败时不给库存扣减，不生成不完整借阅记录。 |
| FR-10 | 并发防超借 | 当多人同时借同一本库存较少的图书时，服务端必须保证库存原子扣减。 | 最后一本只能被一个请求借出；失败请求提示库存不足并要求刷新。 |
| FR-11 | 还书办理 | 支持按借阅单、借阅明细、读者、ISBN、书名搜索未还记录并办理归还。 | 已归还明细不得重复还书，库存不得重复增加。 |
| FR-12 | 部分还书 | 一张借阅单中部分图书归还后，未还图书仍保持借阅中。 | 借阅单状态显示为部分归还；全部明细归还后显示已归还。 |
| FR-13 | 逾期查询 | 系统按当前日期判断超出应还日期且未归还的图书。 | 展示逾期天数，支持按读者和图书筛选并跳转还书。 |
| FR-14 | 借阅记录 | 记录查询应展示读者姓名、借阅证号、图书名称、ISBN、借还日期、状态和操作人。 | 历史记录保存快照，后续修改读者或图书资料不影响历史展示。 |
| FR-15 | 读者自助借书 | 普通读者在软件的读者自助端登录后检索图书、选择可借图书、确认借阅。 | 自助端同样执行库存、状态、上限和重复借阅校验，读者不能进入管理员功能。 |
| FR-16 | 读者自助还书 | 普通读者在软件的读者自助端查看本人未还图书，可选择一部分或全部归还。 | 自助还书后更新明细状态、归还时间和库存，且只能处理本人借阅记录。 |
| FR-17 | 提示与状态 | 页面统一显示加载、空数据、成功、失败、确认和防重复点击状态。 | 用户能明确知道操作是否成功以及失败原因。 |
| FR-18 | 初始业务数据 | 提供可重复执行的初始化脚本和用于验收的业务数据。 | 验收数据覆盖多本借阅、部分还书、无库存、逾期、停用、并发边界。 |

## 6. 业务规则
| 规则 | 说明 |
| --- | --- |
| 借阅上限 | 同一读者同时未还图书数量不得超过系统设定上限，默认 5 本，可在需求审核时确认。 |
| 一次多本提交 | 一次借阅可选择多本图书。若任一图书不满足条件，默认整单不提交，并提示需要调整；是否允许成功借出可借部分需审核确认。 |
| 部分还书 | 借阅明细逐本归还。部分归还不结束整张借阅单，全部归还后整单结束。 |
| 库存口径 | 馆藏总数 = 可借数量 + 已借出数量 + 不可借/停用数量。任何业务操作后库存数字必须保持一致。 |
| 货架位置 | 每本图书资料至少记录一个默认书架位置；如后续管理到副本级，可精确到具体副本所在货架。 |
| 并发借阅 | 借阅提交必须在服务端事务中完成库存判断和扣减，库存不足时失败，不允许出现负库存。 |
| 重复借阅 | 同一读者未归还同一本图书时，默认禁止再次借同一 ISBN；如按副本允许多册，需审核确认。 |
| 历史快照 | 借阅记录中保留读者姓名、借阅证号、图书 ISBN、书名、作者等快照，避免历史被后续资料修改影响。 |
| 停用规则 | 停用读者/图书不能发起新借阅；已经借出的图书仍可归还，历史记录继续保留。 |
| 逾期规则 | 当前日期超过应还日期且未归还即视为逾期；本阶段只显示逾期，不强制计算罚款。 |
| 权限隔离 | 管理员/馆员端与普通读者端分开登录。普通读者只能操作本人借阅信息，不能新增、编辑、删除图书或读者资料。 |

## 7. 真实验收场景
| 场景 | 描述 | 期望结果 |
| --- | --- | --- |
| S-01 正常一次借多本 | 读者到馆选择 3 本书，馆员扫描借阅证和 3 本图书，确认应还日期后提交。 | 系统生成 1 张借阅单和 3 条明细，3 本书库存分别减少 1。 |
| S-02 部分还书 | 读者上次借了 3 本，本次只还 1 本。 | 该明细变为已归还并恢复库存，借阅单状态为部分归还，剩余 2 本仍显示未还。 |
| S-03 全部还清 | 读者将同一借阅单剩余图书全部归还。 | 全部明细已归还，借阅单状态变为已归还，不再出现在未还列表。 |
| S-04 库存不足 | 某书可借数量为 0，读者仍尝试借阅。 | 系统禁止提交，提示库存不足，不生成借阅记录。 |
| S-05 并发抢最后一本 | 两个窗口同时借同一本只剩 1 册的图书。 | 只有一个请求成功，另一个请求提示库存不足，库存不会变成负数。 |
| S-06 停用读者借书 | 读者状态为停用，但仍尝试借书。 | 系统禁止新借阅；若有未还图书仍可办理归还。 |
| S-07 读者自助借书 | 读者在自助端登录，搜索图书并选择多本可借图书。 | 系统执行同样校验，成功后生成借阅单并展示应还日期。 |
| S-08 读者自助还书 | 读者在自助端查看本人当前借阅，只选择其中 2 本归还。 | 系统完成部分还书，未选择的图书仍保留为借阅中。 |
| S-09 货架查询 | 馆员或读者查询一本书。 | 详情展示分类、可借数量和书架位置，便于找到实体书。 |
| S-10 逾期处理 | 某读者图书超过应还日期未归还。 | 逾期列表显示读者、图书、应还日期和逾期天数，可直接办理归还。 |

## 9. 非功能需求
| 类别 | 要求 |
| --- | --- |
| 数据一致性 | 借书、还书、库存扣减和记录状态更新必须在服务端事务内完成。 |
| 安全性 | 敏感配置不提交到公开仓库；后台接口必须登录后访问；错误信息不暴露堆栈。 |
| 易用性 | 页面有明确的中文提示、加载状态、空状态、重置按钮和二次确认。 |
| 可追溯性 | 借阅和归还记录保留操作时间、操作人、读者和图书快照。 |
| 可维护性 | 需求审核通过后再进行数据库、UML、接口和代码设计，保证命名一致。 |
| 性能 | 常用列表分页查询；读者、图书、借阅记录按常用条件建立索引。 |
| 兼容性 | 系统应能在 Windows 环境下使用 IntelliJ IDEA、MySQL/MariaDB 和浏览器完成部署、运行和验收。 |

## 10. 待审核确认项
| 编号 | 确认问题 | 建议 |
| --- | --- | --- |
| T-01 | 一次借多本时，若其中一本库存不足，是整单失败，还是允许其他可借图书成功？ | 建议整单失败，便于保证业务清晰。 |
| T-02 | 同一读者是否允许一次借同一 ISBN 的多本副本？ | 建议默认不允许，除非老师要求按副本管理。 |
| T-03 | 读者自助登录方式使用借阅证号 + 密码，还是扫码/刷卡模拟？ | 建议初版使用借阅证号 + 密码。 |
| T-04 | 是否需要罚款、预约、续借等扩展功能？ | 建议本阶段只做逾期展示，不做罚款结算。 |
| T-05 | 库存是否管理到具体副本编号？ | 建议需求中保留副本概念，设计阶段根据时间决定是否落表。 |
